# МСА «АгроТех Х» — проектная работа

Учебный проект по микросервисной архитектуре (Яндекс Практикум).

«АгроТех Х» занимается растениеводством и свиноводством: 150 площадок, свой парк техники, разнородный IT-ландшафт. Задача — спроектировать MVP платформы мониторинга скота: видеоаналитика поведения животных, биометрия с носимых датчиков, управление кормушками и поилками, оповещение сотрудников. Ферма должна работать без интернета, а на оповещение о ЧП есть 5 секунд.

## Ключевые решения

- **Аналитика на ферме.** Видео обрабатывается на месте, в центр уходят только события и метрики. Иначе не выполнить требования «5 секунд» и «работа без интернета» на нестабильном канале.
- **Центральная система одна**, агентов столько, сколько ферм. Задержка синхронизации до 10 минут допустима, при обрыве связи агент копит данные и досылает их позже.
- **Kafka на ферме и в центре** — publish/subscribe вместо прямых вызовов: сервисы не зависят от доступности соседа. Технология уже используется в компании.
- **Оборудование и датчики — через MQTT** с мостом в Kafka: Kafka не понимает MQTT, а устройства работают только по нему.
- **Кадры берутся из ERP 1С:Агро**, а животные, загоны и график дежурств — свои данные платформы.
- **В SaaS данные клиентов разделяются схемами БД**, крупному клиенту можно выделить свою базу или контур.

## Как отрисовать диаграммы

```bash
java -jar plantuml.jar -DRELATIVE_INCLUDE="." -tpng -o . Task1/*.puml Task2/*.puml Task3/*.puml Task5/*.puml
```

Флаг `-DRELATIVE_INCLUDE="."` заставляет шаблон брать `templates/C4.puml` локально; без флага он подтянет C4-PlantUML из интернета.
