# Task 3. Диаграммы C3 и C4

Детализация решений из [Task2](../Task2/) для передачи в разработку.

Разбирается **сервис инцидентов** — он применяет правила к детекциям, биометрии и телеметрии, создаёт инциденты и запускает локальное оповещение, то есть закрывает ФТ 1–3 и отвечает за требование «не более 5 секунд до оповещения». В варианте 1 это отдельный сервис, в варианте 2 — модули внутри общего сервиса фермы.

| Файл | Уровень | Что показывает |
|---|---|---|
| [c3-main.puml](c3-main.puml) | C3 | Компоненты сервиса инцидентов (вариант 1: микросервисы на ферме) |
| [c4-main.puml](c4-main.puml) | C4 | Код сервиса инцидентов: приём событий, правила, хранение, публикация |
| [c3-alternative.puml](c3-alternative.puml) | C3 | Компоненты сервиса фермы (вариант 2: модульный монолит) |
| [c4-alternative.puml](c4-alternative.puml) | C4 | Код сервиса фермы: модули, шина в процессе, правила, хранение |

Чем варианты отличаются на этих уровнях:

- В варианте 1 события приходят и уходят через адаптеры Kafka, домен о брокере не знает. В варианте 2 модули общаются через шину внутри процесса, адаптеры не нужны.
- Набор правил в обоих вариантах одинаковый: новое правило — это новый класс, реализующий общий интерфейс, существующие не меняются (НФТ 4).
- В варианте 2 все модули собираются и перезапускаются вместе, поэтому ошибка в одном модуле останавливает остальные (НФТ 3).

## Как отрисовать диаграммы

```bash
java -jar plantuml.jar -DRELATIVE_INCLUDE="." -tpng -o . Task3/*.puml
```
